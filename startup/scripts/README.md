prod_update.sh — инструкции

Цель
- Автоматизировать безопасное обновление продакшен-кодовой базы: сделать git reset, создать дамп Postgres, пересобрать и поднять Docker Compose, показать журналы и выполнить базовую проверку API.

Как использовать
1. Скопируйте `prod_update.sh` на сервер в папку `startup/scripts/` проекта.
2. Сделайте исполняемым:
   ```bash
   chmod +x startup/scripts/prod_update.sh
   ```
3. Запустите (рекомендуется от root или пользователя с доступом к docker):
   ```bash
   sudo startup/scripts/prod_update.sh main /tmp
   ```
   Параметры: ветка (по умолчанию `main`) и директория для бэкапа (по умолчанию `/tmp`).

Что делает скрипт
- `git fetch && git reset --hard origin/<branch>`
- Ищет контейнер базы данных (compose service `db` или первый postgres-образ)
- Делает дамп базы `pg_dump` и сжимает его в `.gz` в указанной директории
- `docker compose pull` + `docker compose up -d --build` (или `docker-compose` при отсутствии встроенного)
- Показывает логи `backend` и `nginx` (последние 200 строк)
- Выполняет базовую проверку API `https://localhost/api/doctors/?page=1`

Безопасность и предостережения
- Скрипт НЕ выполняет восстановление или модификацию данных. Он только создаёт дамп.
- Перед любыми операциями по изменению кодировки или массовой миграции данных обязательно загрузите дамп на локальную машину и проверьте его в тестовой среде.
- Убедитесь, что доступ по SSH к серверу настроен безопасно (ключи), и что у вас есть резервные копии вне корня проекта.

Если нужно
- Могу сгенерировать отдельный скрипт/инструкции для безопасной починки кодировок (CP866 → UTF-8) на копии дампа и для развёртывания результата.
